## Anti-pattern verdict: does this look AI-generated?

**No — and not by accident.** If someone claimed an AI made this, I would not
believe them. The specific reasons:

- Monospace-only type (Departure Mono + Commit Mono). No serif-display + geometric-sans
  pairing, which is *the* generated-interface tell.
- Neutral grayscale with exactly one chromatic accent, used maybe three times per card.
- No gradient text, no glassmorphism, no soft-rounded everything, no icon-above-heading
  card grid, no hero metric block.
- The v2.1 removal of the 3px left-stripe callout in favour of a 1px hairline
  deleted the single most overused "design touch" in this category before a
  detector ever ran.

**Deterministic scan:** 156 findings across the specimen, but they collapse into
four classes and most do not apply to the product:

| Finding | Count | Verdict |
|---|---|---|
| `undersized-ui-text` (<11px) | 115 | **Partly real.** Most are the specimen's annotation layer, but the shipped action row is genuinely 10.5px — see P2. |
| `all-caps-body` | 12 | **Mostly false positive.** 10 of 12 are `.chrome-caption`, the specimen's own annotation scaffolding, which CLAUDE.md already lists as dead. One is real: `.status`. |
| `tiny-text` | 19 | Same population as above. |
| `gpt-thin-border-wide-shadow` | 9 | **One is real** — see P3. |
| `em-dash-overuse` | 1 | False positive: specimen prose, not product copy. |

Zero AI-slop antipatterns fired. The detector found quality issues, not identity issues.

## What's working

1. **The extraction sequence is the best thing here.** Skeleton → "reading page" chyron
   → filmstrip → filled card gives the user something true to watch during the one
   genuinely slow, genuinely billed moment. Most products put a spinner here.
2. **Red is disciplined.** Principle 6 — red means action *or* failure, never both on
   one screen — is a real constraint, and the error row honouring it by making Retry
   bone-filled rather than red is the kind of decision most systems talk about and
   then quietly break.
3. **The error state respects the user's intelligence.** It names a cause, offers
   ranked fallbacks, and drops RETRY entirely when retrying cannot help.

## Priority issues

### [P0] There is no route to an API key

**What:** Prep asks for an Anthropic API key. The hint explains where it is *sent*
("Stored on this device only. Sent to api.anthropic.com and nowhere else") but never
where to *get one*. There is no link, no `NO API KEY` error affordance pointing
anywhere, and no first-run guidance.

**Why it matters:** This is a BYOK product, so the key is not one setting among
several — it is the gate in front of every single feature. A user who does not
already have a Claude API key cannot use Mise at all, and nothing in the interface
tells them that is even the problem to solve. This is the highest-leverage fix on
the list and it is roughly one anchor tag.

**Fix:** Link `console.anthropic.com/settings/keys` from the Prep hint, and from the
`NO API KEY` error's fallback list. Consider one line on cost, since "how much will
this bill me" is the immediate next question.

**Command:** `/clarify`

---

### [P1] The specimen has drifted from the product, and the specimen generates the CSS

**What:** `type-specimens/popup-states.html` still renders `Keep open` (×2) and `.pdf`
(×6) in its resolution states. The 2026-08-18 navigation decision removed `Keep open`
entirely — `popup.ts:404` mentions it only in a comment explaining why it is gone —
and parked PDF export.

**Why it matters:** This is not cosmetic doc rot. `popup.css` is *generated from the
specimen* by `port-design.mjs`, and CLAUDE.md's rule is "change the specimen, run a
desk crit, then `npm run port:design`." A stale specimen means the next person to run
that pipeline regenerates CSS for controls that no longer exist, and the crit surface
shows a product that no longer ships. The design source of truth is currently wrong.

**Fix:** Update the resolution states in the specimen to match the shipped action
rows, then re-run `port:design`. This is the one finding that gets worse with time.

**Command:** `/polish`

---

### [P2] The window's entire navigation is set at 10.5px

**What:** Measured in-browser: `.popup-actions .secondary-btn` — Prep, Archive, Copy —
renders at **10.5px uppercase with 1.26px tracking**, against the primary action's
12px. Hit boxes are 34px tall, which is fine; the problem is legibility, not target size.

**Why it matters:** All-caps at wide tracking is the *hardest* combination to read at
small sizes, because uppercase removes the ascender/descender word-shape cues the eye
uses. And these are not decorative chrome — since the 2026-08-18 decision, Prep and
Archive *are* the only navigation this window has. The receipt metaphor earns tiny
type for the ticket header, the timestamp, the tag line. It does not obviously earn it
for the primary means of moving around the product.

**Fix:** Take the secondary row to 11.5–12px and reduce tracking to ~0.06em. The
receipt texture survives; it lives in `.ticket-top`, `.meta` and `.tags`, which can
stay small because nobody has to click them. **Owed a desk crit** — this trades brand
texture for legibility and that trade is Ben's call, not mine.

**Command:** `/typeset`

### [P3] Two smaller structural issues

**a) The flame focus ring re-breaks Principle 6.** `:focus-visible` is a global
`2px solid var(--flame)`. On the Kitchen Error screen, red means failure — and the
error row deliberately makes Retry bone-filled to keep it that way. Tabbing to that
button paints a red ring around it, reintroducing exactly the ambiguity the principle
was written to remove. Consider a neutral (`--ink`) ring, or a flame ring everywhere
*except* the error surface.

**b) The archive renders up to 500 rows unvirtualized.** `storage.ts:18` caps history
at `MAX_HISTORY = 500` and `archive.ts` maps the filtered list straight into the DOM.
At 500 two-line rows in a 400px popup this will be felt on open. The guideline
threshold is 50.

**Also, quickly:**
- No `color-scheme` declared. The Model `<select>` in Prep is a native control on a
  paper-white surface; under a dark OS theme Chrome may render it dark. One line fixes it.
- `.status` sets 38 characters of uppercase at 10px ("Multiple recipes detected —
  which one?"). That is a sentence, not a label.

~~No `tabular-nums` anywhere.~~ **Retracted.** Every font token — `--font-display`,
`--font-body`, `--font-mono` — resolves to Departure Mono or Commit Mono. The system
is monospace throughout, so figures are already fixed-width and `tabular-nums` would
be a no-op. Checked before shipping the change rather than after.

**Command:** `/polish`, then `/audit`

## Persona red flags

**Jordan (first-timer, has a recipe open, has never heard of an API key).**
Opens Mise expecting it to just work. Gets `NO API KEY`. Opens Prep, sees a field
wanting `sk-ant-…`, and there is nothing anywhere telling them what that is or where
to get one. **They abandon here** — and this is the single most likely first
experience, because nobody arrives already holding a Claude key. Then, if they push
through: `OFF MENU` on a page Mise cannot read tells them the product's state, not
what they should do instead.

**Alex (power user, fires twenty recipes a week).**
Well served — `⌘⇧M`, `Esc`, selection capture via context menu, the archive with
search. Two frictions: the archive's 500 rows are exactly the case they will hit
first and feel; and the 10.5px nav they will be clicking dozens of times a week is
the smallest text in the window.

**Ben (the designer, reading the specimen as source of truth).**
Reads a specimen showing `Keep open` and `.pdf`, neither of which exists. Any crit
run against that surface critiques a product that no longer ships.

## Questions worth sitting with

1. **Does the receipt metaphor earn 10.5px on the *navigation*, or only on the
   chrome?** The ticket header being tiny is texture. Prep and Archive being tiny is
   a tax the user pays on every trip.
2. **`OFF MENU` is a great name for the state. Is it a good name for the moment?**
   It tells the user what Mise thinks. It does not tell them what to do — and the
   panel underneath already does that work well.
3. **The pulse now tells the user a page has a recipe before they open the popup.
   Does the empty state still need to work as hard?** Detection has moved upstream;
   the interior states may be able to relax.
